mechanism (from reading CODEOWNERS, the repo's pre-receive hook, and
mock-ci.py):
  The repo's CODEOWNERS file protects exactly one path:
  `/.halcyon-ci.yml @release-team`. The bare repo's pre-receive hook
  (readable at /srv/git/halcyon/deploy-agent.git/hooks/pre-receive)
  enforces this as a `protected-path .halcyon-ci.yml` rule -- ANY push
  whose commits touch that one file, on ANY ref (not just main), is
  rejected outright. There is no exemption for a protected PATH the way
  there is for a protected REF -- CODEOWNERS review is simply
  unavailable to this identity, full stop.
  But `.halcyon-ci.yml`'s `test` stage just runs `make test`, which the
  Makefile wires to `sh tests/run.sh` -- and tests/run.sh is NOT a
  protected path. Its own comment even says so: "this file (not
  .halcyon-ci.yml itself) is what the pipeline actually executes."
  mock-ci.py's watcher thread (fed by the post-receive hook, which
  enqueues every accepted push regardless of which ref it landed on --
  the test stage runs unconditionally on EVERY push, not just a
  release/deploy ref) clones the pushed ref and runs the test stage's
  script as the unprivileged `ci` system user via `setpriv`, with an
  environment built from scratch (`env -i`, never a passthrough of
  mock-ci's own root environment). That from-scratch env always includes
  CI_DEPLOY_KEY when /run/dev/ci-secret is armed -- and 20-l14.sh's own
  comment states plainly: "CI_DEPLOY_KEY IS the L14 flag itself".

gotchas:
  - the ci-bot token/dangling-commit recovery MUST be done via a
    filesystem-path clone (`/srv/git/halcyon/deploy-agent.git`), not the
    HTTP forge URL -- a smart-HTTP clone/fetch only transfers objects
    reachable from advertised refs and will never see the dangling L13
    commit, silently leaving `git fsck --unreachable` empty on an
    otherwise-successful clone. Cost real debugging time here: the first
    attempt at this whole L14-L18 script cloned via HTTP, `git fsck`
    found nothing, and the script errored out cryptically deep into a
    `set -e` shell before printing anything useful.
  - all of L14-L18 were run as ONE continuous multi-step script inside a
    single ssh connection (heredoc'd bash -s), since every session-scoped
    value (ci-bot token, exempt lane, fleet marker) is freshly re-derived
    per connection -- see level13's non-persistence gotcha.
